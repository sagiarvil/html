PUBLIC METHODOLOGY / VERSION 2.0

Every score must have a traceable reason.

HTML&HTML publishes the decision model behind its 12-engine validator. Standards, vendor guidance, proposals, direct measurements and internal heuristics are explicitly separated so a 100/100 score cannot imply more than was actually measured.

01 / EVIDENCE

Source classes are not interchangeable.

A rule receives a source class before it can influence interpretation. Normative force is part of the result, not hidden implementation detail.

OFFICIAL_STANDARD

Normative standards and protocols

Standards with formal or normative authority, such as the Robots Exclusion Protocol and established web platform behavior.

Highest normative weight
OFFICIAL_VENDOR

Current vendor documentation

First-party crawler or product guidance from the organization operating the relevant system. Vendor behavior can change; rules are versioned and must be rechecked.

Current behavior, not universal standard
PROPOSAL

Emerging proposals

Conventions such as llms.txt are useful but are not presented as mandatory web standards or ranking requirements.

Explicitly non-mandatory
MEASURED

Direct observation

HTTP status, headers, HTML, robots content, schema parse state, link response and other externally observable facts collected by the scanner.

Direct evidence
INTERNAL_HEURISTIC

Product heuristics

Decision-support rules created by HTML&HTML where no formal standard defines a pass/fail threshold. These must never masquerade as vendor or standards requirements.

Product judgment
EXPERIMENTAL

Early agent surfaces

Experimental or low-adoption agent-facing mechanisms are isolated from mature crawl/indexing requirements and receive limited decision weight.

Low certainty / forward signal
02 / CONFIDENCE

Evidence strength travels with every finding.

The scanner distinguishes what was directly observed from what still needs source-code or operational verification.

CONFIRMED

Directly measured

The public response itself proves the condition: HTTP, HTML, header, robots or link evidence.

STRONG

Multiple signals agree

Several independent public signals converge, but the root cause may still live outside the observable surface.

PROBABLE

Useful but incomplete

The evidence supports the finding without proving every internal mechanism behind it.

REQUIRES SOURCE

Codebase verification required

Public scanning can show behavior but cannot safely invent the file, function or deployment layer that must change.

03 / SCORING

Unknown is not failure. Unknown is not success.

Each engine calculates a weighted score from rules that are actually measurable in the current scan. Rules with unavailable evidence are excluded from the denominator rather than forced to pass or fail.

StateIncluded in denominatorScore contributionInterpretation
PASSYesWeighted passMeasured condition satisfied
FAILYes0 for that ruleMeasured condition not satisfied
UNKNOWN / NOT_MEASUREDNoNoneInsufficient reliable evidence

The overall score aggregates twelve category scores: Crawl & Index, Technical SEO, AI/GEO Access, llms.txt v2, Structured Data, Performance Hygiene, Accessibility, Security Baseline, Content Trust, Agent Readiness, Conversion and Link Integrity. A score is a diagnostic state, never a ranking, revenue or AI-citation guarantee.

04 / BOUNDARIES

The scanner is deliberately constrained.

Production safety and epistemic safety are both part of the methodology.

NETWORK

SSRF fail-closed

Private/local/reserved targets, credential-bearing URLs, non-standard ports and redirect pivots into private address space are rejected. DNS is checked before fetch.

CRAWL

Bounded public scan

The engine caps page discovery, response size, redirect depth, request time and link probes to avoid turning a diagnostic tool into an uncontrolled crawler.

FIELD DATA

No fabricated Core Web Vitals

LCP, INP and CLS are not inferred from static HTML. Without a reliable field/lab integration they remain NOT_MEASURED.

SOURCE CODE

No invented file paths

Public behavior can identify a defect class, but precise source-file targeting requires repository/codebase context.

COMMERCIAL

Evidence stays free

Issue, URL, severity, confidence, source class and evidence are public. The paid layer sells implementation sequence, root fix, recovery, prevention, tests and rollback.

ENTITLEMENT

Paid endpoint fails closed

Implementation output must not become publicly callable merely because payment infrastructure is incomplete or misconfigured.

05 / GOVERNANCE

External rules must be revalidated, not memorized.

Vendor crawler names, policies and emerging proposals can change. HTML&HTML treats source freshness as a dependency of the rule set.

llms.txt

Proposal reference

llmstxt.org is tracked as a PROPOSAL source. The August 2026 v2 revision added rel="describedby" and Markdown alternate discovery while keeping the file format compatible.

OpenAI

Search crawler eligibility

OpenAI search documentation is treated as OFFICIAL_VENDOR guidance for OAI-SearchBot access. Eligibility does not imply placement or citation.

Robots

Protocol interpretation

Google's robots.txt documentation and the underlying Robots Exclusion Protocol are used to separate generic robots behavior from vendor-specific product controls.

Run the methodology against a real domain.

The public scanner returns the measured result and evidence. Specialized authority pages expose narrower llms.txt and AI-crawler views without creating separate scoring engines.
