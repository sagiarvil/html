# HTML&HTML Product Disclosure Standard

Every product detail page must disclose enough information for a buyer to understand deployment and integration before purchase.

Required fields:
- business category and intended use
- price and complexity level
- canonical technology stack
- build-step requirement
- responsive preview for desktop, laptop/tablet and mobile
- browser target (do not call it verified compatibility without evidence)
- direct deployment targets
- framework adaptation targets
- platforms requiring theme/adapter work
- implementation method
- checkout/release status
- support/update promises only when actually offered

Compatibility vocabulary:
- DIRECT: the canonical HTML package can be deployed without framework conversion.
- ADAPTABLE: source structure can be converted into the target framework; work and testing are required.
- THEME / ADAPTER WORK: platform-specific integration is required.
- VERIFIED: may be used only when evidence exists for the exact claim.

Do not claim one executable codebase runs unchanged across all frameworks or CMS platforms.
