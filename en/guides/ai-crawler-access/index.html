AI Crawler Access: Robots.txt, Search Retrieval and Vendor-Specific Controls

A vendor-sourced guide to separating search crawlers, user-directed retrieval and model-development collection controls.

01

Robots rules are protocol behavior, vendor meaning is separate

RFC 9309 defines the Robots Exclusion Protocol. Vendor documentation defines what each crawler token is used for. A correct audit needs both layers because a syntactically valid robots rule does not explain the product purpose of a bot.

02

OpenAI search access is not a placement guarantee

OpenAI documents OAI-SearchBot for search eligibility. Allowing access can be a prerequisite for inclusion, but it does not guarantee placement, ranking or citation. GPTBot and search access should not be treated as the same control.

03

Anthropic exposes distinct crawler roles

Anthropic documents separate crawler identities for model-development collection, user-directed retrieval and search. Treating them as one generic “Claude bot” loses policy precision and can cause unintended blocking.

04

Perplexity and Google require their own reading

Perplexity documents robots behavior for PerplexityBot. Google documents common crawlers and Google-Extended separately. A single “allow AI” switch is therefore not a reliable governance model.

05

Test the live robots response

Do not audit a robots file from a CMS editor alone. Fetch the deployed robots.txt, follow redirects, resolve the effective user-agent groups and verify that the public site returns the policy you intended.
