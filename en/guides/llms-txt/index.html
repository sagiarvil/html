llms.txt: What It Is, What It Is Not, and How to Validate It

A sourced guide to llms.txt v2, discovery relationships, link reachability and the limits of the proposal.

01

llms.txt is a proposal, not a mandatory ranking standard

The file is useful as an emerging convention for presenting a concise, LLM-oriented map of a site. It should not be described as an IETF, W3C or search-ranking requirement. That distinction belongs in both product messaging and scoring.

02

Structure is only the first check

A text file can be syntactically clean while pointing to broken or redirected resources. Validation should therefore separate Markdown structure from real HTTP reachability and report each failure with its own evidence.

03

Discovery matters

The current proposal includes discovery mechanisms such as rel="describedby" and Markdown alternate relationships. These are useful signals for machine discovery, but they remain proposal-level behavior and should not be scored like normative web protocol requirements.

04

Keep linked resources purposeful

An llms.txt file is more useful when it points to stable, canonical, high-information pages rather than a long list of thin URLs. A strong site information architecture makes the file easier to maintain and easier for retrieval systems to navigate.

05

Validate after deployment

Changes to routing, redirects or content types can silently break linked resources. Re-run the validator after deployment and treat the file as part of the site’s maintained machine-readable surface.
