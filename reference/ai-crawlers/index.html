Do not treat every AI bot as the same crawler.

Search inclusion, user-directed retrieval, model-development collection and product-control tokens are different mechanisms. This reference preserves those distinctions and links each behavior to a first-party source.

02 / DECISION RULES

Four distinctions prevent most configuration errors.

SEARCH ≠ TRAINING

Separate visibility from model development

OAI-SearchBot and GPTBot are not interchangeable. Claude-SearchBot/Claude-User and ClaudeBot also represent different use cases.

TOKEN ≠ HTTP UA

Google-Extended is a control token

Google states Google-Extended has no separate HTTP request user-agent string; existing Google crawlers perform fetching while the robots token controls specified downstream uses.

ROBOTS ≠ AUTH

robots.txt is not access control

RFC 9309 specifies crawler preferences and explicitly does not make robots.txt an authorization mechanism. Sensitive resources require real authentication/authorization.

ALLOW ≠ RANK

Crawl eligibility is not placement

Allowing a search crawler removes one technical barrier. It does not guarantee indexing, selection, ranking, answer inclusion or citation.
